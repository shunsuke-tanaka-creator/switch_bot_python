# GPSを使わない拠点・タスク推定

## 今回の変更

`/research/p001/context` に現在の候補・推定、本人確認、命名、時間区間の訂正、統合、1日の振り返りを追加した。iPhoneの「生活の気づき → 履歴・傾向・トポロジー → 拠点とタスク」から開ける。

拠点とタスクは別のID・特徴空間・本人回答を持つ。同じ机で仕事からゲームへ切り替えた場合は拠点を維持してタスクを変更する。別の場所でも同じ仕事をするならタスクを維持する。部屋名や文章だけで拠点の境界を決定しない。

GPS訪問・匿名GPS場所ID・Wi-Fi識別情報・BLEのRSSIを使用しない。SwitchBotの開閉状態、入力操作・確定本文、鮮度付きの端末Context、時刻・曜日は使用する。既存の過去ログは削除しない。旧iPhoneから届く `place_visit` は成功応答で受け流し、追加保存しない。既存GPSマップから行き先の質問も生成しない。

## 学習と限界

- `ContextLSTM` は既存と同じMicro（5分〜1時間）、Meso（日）、Macro（過去4週＋当週）の三階層構造を用いる。疲労などの既存モデルとはチェックポイント・学習ゲートを分離する。疲労の回答不足で拠点の学習まで止まらない。
- 共通の三階層表現から、32次元の拠点表現と32次元のタスク表現を別々に出す。次の1時間の観測特徴を予測する自己教師あり損失と、本人確認済みの同一軸のIDを近づけ、異なるIDを離す損失を併用する。タスクの違いを自動的に別拠点の正解にしない。
- 本人の回答・訂正・モデル推定は入力特徴にしない。質問回答操作も既存の `purpose=assessment` により除外する。取得できないセンサー値をゼロとして観測した扱いにしない。
- 直近28日・最大240時点を対象にする。最小12時点・3日を要求し、さらに日単位の学習/検証/テスト分割が必要。これは学習を開始する下限であり、精度を保証する条件ではない。1週間から開始できるが、曜日ごとの習慣には複数週必要。
- 正規化は学習側だけで計算。訓練には境界前に届いていた回答と統合情報だけを使う。遅れた訂正で当時有効だった回答を消さない。自己教師ありの次時点ターゲットも分割境界をまたがせない。テストは明示した比較実行時のみ評価する。
- 未回答の観測は正解ラベルにしない。未知のまとまりは特徴の類似性から自動作成するが、**拠点かタスクかの意味を保証するのは本人確認を含む学習であり、無回答だけで分離できる保証はない**。候補は確定表示しない。
- 初期の探索的表示条件は、同じクラスの学習支持2日以上、軸の検証2件以上・正解率0.5以上、類似度0.8以上、次候補との差0.08以上。単一候補だけでは確定しない。類似度0.65未満は候補IDも表示しない。これらの値は実データで校正済みの確率ではない。
- 未学習・観測が古い・モデルが予測時刻より未来に学習された場合は、モデルの場所・タスクを表示しない。固定ドアの定期広告だけで本人の存在を確定しない。新しい回答・分割・統合が入ると、再学習するまで古いモデルの断定を抑制する。
- 再学習時は命名済みIDと候補の元観測を新しいモデルで再埋め込みする。古い重心と新しい埋め込みを混ぜない。未確認候補は各軸64個を上限にし、本人が作成したIDは勝手に消さない。
- `text_model` が設定されていれば既存のローカルSentenceTransformerを使用する。未設定時は文字n-gramであり、**文章の意味理解とは扱わない**。意味を利用する実験では、既存の [モデル配置手順](research.md) に従い同一モデルを設定する。本文を外部APIに送信しない。

## 質問と訂正

`placeCheck` / `taskCheck` は既存の共通質問上限（既定4回/日、60分間隔）を使い、拠点・タスク確認は合計2回/日まで。夜の振り返り枠を残す。質問には既存候補、新しい拠点/タスク、わからない、拠点の場合は移動中を表示する。通常の気分質問や入力修正・支援の質問と同じ予算で制御する。

回答は質問発行時までの5分間のラベルとして保存する。通信が遅れた回答を、その後の新しい場所の正解として使わない。親アプリ・キーボードの回答は永続outboxで再送され、同じ質問IDの重複回答は二重保存しない。

Web画面では任意の過去区間を拠点・タスクそれぞれで訂正できる。分割は区間を選び別IDへ割り当てる操作。統合・命名も追記する。名前だけの変更は学習ラベルを作らない。

## Macでの運用

既存のサーバー設定（IP、許可端末、DB、機器名）を維持したうえで、次の項目を追加/確認する。全体例は `deploy/mac-research.example.json`。例のIPで既存設定を上書きしない。

```json
{
  "research_enabled": true,
  "research_require_cuda": false,
  "research_upstream": "",
  "context_device": "cpu",
  "context_epochs": 12,
  "context_train_interval_seconds": 3600
}
```

学習・推論は別ワーカー。既存収集を継続し、既定では1時間ごとに新規ログを確認して学習、1分ごとに暫定結果を保存する。翌日には前日の振り返りを別レコードに保存する。後からの訂正は画面の「振り返りを作成・更新」で再反映できる。当時のライブ結果は変更しない。

依存関係を更新する（サーバー停止・DB/モデルのバックアップ後）。

```sh
.venv/bin/python -m pip install -r requirements-ml.txt
```

期待：依存パッケージがインストール済み、または `Successfully installed`。
意図しない出力：`ERROR`、対応ホイールなし。PythonとOSに対応したPyTorchを用意し、収集用の既存環境を壊さない。

手動学習と、最終評価を含む比較実行：

```sh
.venv/bin/python -m research.cli --participant p001 context-train --device cpu
.venv/bin/python -m research.cli --participant p001 context-train --device cpu --evaluate-test
```

意味特徴を使う場合は両方に `--text-model /実際のモデル保存先` を付ける。常駐設定の `text_model` と同じものを使用する。
期待：JSONの `status: trained` または、データ不足時の `insufficient_observations` / `insufficient_split`。テスト評価は `test.place` / `test.task`。
意図しない出力：`Traceback`、`text_model must be an existing local model directory`。パス・依存を確認する。合成データの成功は実精度の証明ではない。

## MacからUbuntuへの切り替え

同じコードを使用する。収集はMacに残し、学習・推論だけUbuntuへ移せる。チェックポイントはCPUテンソルとして保存し、MacのCPU・UbuntuのCPU/CUDA間でロードできる。実機のCUDA/MPS動作はこの変更環境では未確認。

1. 一貫した引き継ぎのため、Macの収集・学習サーバーを一時停止する。
2. Macで全記録とモデルを1ファイルに書き出す。

```sh
.venv/bin/python -m research.cli --participant p001 export-bundle data/private/context-transfer.zip
```

期待：`status: exported`、レコード数と保存先。本文を含む非公開の移行ファイルで、Gitへ追加しない。
意図しない出力：`BlockingIOError` は学習ロック競合。停止後に再実行する。

3. ZIPをUbuntuへコピーする。意味特徴を使用している場合、**同じ文章モデルのディレクトリも別途コピー**する。ZIPには外部の文章モデル本体を含めない。
4. Ubuntuの新しい空のDB・モデル保存先へ取り込む。

```sh
.venv/bin/python -m research.cli --participant p001 import-bundle data/private/context-transfer.zip
```

期待：`status: imported` とレコード数。ID・命名・訂正・モデル重みを保持する。
意図しない出力：`Destination participant/models must be empty`、`Bundle integrity failure`。既存データを上書きせず停止する。新しい保存先を指定するか、内容を確認してから移行する。

5. Ubuntuで `deploy/ubuntu.example.json` を参考にIP/許可端末を設定。CPUで使うなら `research_require_cuda: false`、GPUなら対応PyTorchを導入。`context_device` は `cpu` / `cuda` / `auto`、Macへ戻す場合は `cpu`。文章モデルのパスはUbuntu側へ変更できるが、内容が一致しないと推論は停止する。
6. Macは `research_enabled: false`、`research_upstream: "http://UBUNTUのTailscaleIP:8000"` にする。Ubuntuから既存の差分同期を開始する。iPhoneの接続先はMacのまま。詳細は [差分同期の手順](research.md)。upstream設定時はMacの研究ワーカーを停止するため二重学習しない。
7. 両サーバーを起動し、iPhoneからログ受信・質問・拠点画面を確認する。Macへ戻すときも、最新のデータを同じ手順で新しい保存先へ戻し、upstreamを空にする。
