# 共有三階層LSTMの推定結果を用いた適応的休憩支援

実装: `discovery-break-v1`。既存 `life-discovery-v1` の推定器・32次元Place/Behavior射影・DiscoveryMap・学習済み重みは変更しない。追加した判定は医療診断や客観測定ではなく、探索的な行動支援である。

## 設定

```json
{
  "research_architecture": "discovery",
  "research_enabled": true,
  "discovery_support_mode": "shadow"
}
```

既存の設定ファイルは上書きせず、対象設定だけ確認・変更する。旧方式を使っている場合はこの設定を自動適用しない。既定の `research_architecture` は legacy のままであり、legacy の判定・質問契約は変更しない。

- `off`: 新方式の休憩判定を停止する。
- `shadow`（既定）: 実観測を用いて5分単位の判定をSQLiteに保存するが、新方式の質問を発行しない。通常質問と既存の誤入力確認経路は従来の設定に従う。
- `live`: 検証および参加者同意後に明示的に設定し、新方式の休憩支援を発行する。独立した従来の誤入力起点の休憩発行を併用しない（既存の入力修正理由確認は維持）。

Shadow/Liveとも、Mac収集・Ubuntu推論構成では研究推論worker側に設定する。PRのマージだけで運用中の設定を変更しない。Liveに切り替える前に対応iOS版を導入する。既に予約した端末通知は期限まで残る場合があるため、モード停止時は端末通知も確認する。

## 判定

推論器の `current` の疲労・集中度・眠気のみを用いる。各尺度は既存の推定表示条件を満たす場合に限る。Behavior ID は `estimated` の確定済みIDのみを用い、過去回答の対象時刻と本人のタスク確認区間（優先）、またはその時点で利用可能だった直近5分以内の推定Behavior IDを対応づける。ID統合はその時点で利用できたaliasを解決する。

- 過去56日の本人の通常現在状態回答について、同一Behavior・尺度で異なる3日以上の回答があれば日別平均の平均と標準偏差を使用する。標準偏差の下限0.5。
- 不明・不足時は既存 `baseline.conditional()`（原則5日以上・時間帯と曜日の重み付き個人基準）に戻る。個人基準も不足する尺度は判定しない。
- 休憩前後の評価回答は介入効果用であり、通常の学習ラベル・基準値・学習fingerprintには混ぜない。

方向を疲労/眠気は増加、集中度は減少に統一する。方向を d（+1または−1）とし、差分 = d × (推定値−基準平均)、Z = 差分 / max(標準偏差, 0.5)、30分変化 = d × (現在推定値−30分前推定値) とする。

| 判定 | 疲労/眠気 | 集中度 |
| --- | --- | --- |
| 絶対値 | 4.0以上 | 2.0以下 |
| 相対値 | 差分1.0以上 かつ Z 2.0以上 | 同じ方向統一後の条件 |
| 30分変化 | 増加1.0以上 かつ現在3.0以上 | 減少1.0以上 かつ現在3.0以下 |

同じ尺度・同じ判定条件が、実観測を伴う連続した完成済み5分区間で2回成立した場合のみ候補化する。時系列比較は同じモデルIDに限定する。相対値の持続判定はBehavior別基準が切り替わった場合に成立させない。モデルが更新されると前モデルの判定は発行しない。30分前の観測がなければ変化判定のみ利用しない。

上記は検証前の閾値。必要に応じ `discovery_support_high`、`discovery_support_low_focus`、`discovery_support_delta`、`discovery_support_z`、`discovery_support_trend_delta`、`discovery_support_trend_floor` を設定可能。再学習は不要。

## 行動選択・質問

3尺度の絶対値・正方向の平均との差・時間変化から0〜1の発火強度を作り、固定のsingleton重み付きルールで短い休憩/軽い気分転換/作業の切り替えを順位付けする。過去の明示的な有用性評価を加味する。強化学習や追加ニューラルネットワークは使わない。

Liveでは既存の質問キューとiOSフォームを再利用し、以下を同一エピソードとして紐づける。

1. `currentState` (`support_pre:`)：介入前5尺度。全項目回答時のみ次へ。スキップ・期限切れ・拒否は無理に進めない。
2. `breakCheck` (`support_discovery:`)：既存3行動を選択、または「今はしない」「提案を停止」。
3. `supportOutcome` (`support_outcome:`)：受諾後15分〜3時間の範囲で実行有無・役立ったかを本人に確認。実行しなかった場合は後評価を発行しない。
4. `currentState` (`support_post:`)：実行確認後30分以内に介入後5尺度を尋ねる。

日中の新規介入は2回まで（本人設定が少なければその値）。未完了/拒否でも開始回数に含む。総質問上限は既存共通予算、夜枠を保持し、エピソード開始時に4件分の空きを要求する。従って既定4件では発行しない。1エピソードと通常質問を両立するには8件程度、2エピソードと通常質問4件を両立するには12件が目安。本人が設定するまで上限を自動変更しない。通常の質問間隔を満たすのは開始時、同一エピソードの後続に限り通常間隔を免除する。予定中、質問停止、提案停止、期限、総予算は引き続き守る。後続回答の提示はアプリの問い合わせ・iOS通知実行時刻に依存する。

## 記録と検証

- `support_decision`: 5分区間ID、使用モデルID、運用モード、Behavior ID、尺度ごとの基準・日数・平均との差・Z・30分変化・条件、判定理由、行動順位。これは提示可能性や因果的な効果を示さない。
- `question_issued` と `narrative`: 既存記録で介入IDの対応を保持。
- `support_effect`: 実行確認済みで紐づいた本人回答がある場合に、各尺度の前後値と差分、有用性を保存する。5尺度すべての前後値があるときのみ符号を揃えた平均改善量（気分・集中度は増加、他3尺度は減少）を保存する。欠測は欠測として残す。自然回復や選択バイアスがあるため因果効果とは扱わない。

`GET /api/research/{participant}/insights` と `proposal-preview` の `support` で判定根拠を確認できる。実データは既存exportや `GET /api/records/{participant}/support_decision/{id}` から監査可能。sampleは合成データのみで過去の区間を仮想再推論する読取専用プレビュー。学習済みsampleモデルを過去区間に適用するため精度評価ではない。combinedでは参加者・履歴を混合した支援をしない。sample/combinedから実質問・支援ログを生成しない。
