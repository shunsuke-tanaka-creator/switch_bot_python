# 共有三階層LSTMによる生活パターン発見

実装版: `life-discovery-v1`。24クラスの活動分類と独立したTask推定を同時に動かす構成を、共有表現からの拠点・行動パターン・5尺度の推定へ置き換える実験的経路である。既存システムは比較条件として保存する。PRのマージだけでは本番の方式は切り替わらない。

## 何を推定するか

- **Place**: GPSによらない拠点の32次元表現と、本人が確認した拠点IDに対する候補・推定。
- **Behavior**: あらかじめカテゴリを24個に固定しない32次元表現と、その空間で発見する行動パターン。
- **現在・日次5尺度**: 気分、疲労、ストレス、集中度、眠気の本人回答に対する推定。診断や客観測定ではない。

`task` は既存API・質問・保存データの互換名で、新方式ではBehaviorと同じ軸を指す。Task用の別LSTMは動かさない。24活動の回答は削除せず、学習後の行動ノードの説明件数と、旧分類器の比較実験に使う。新モデルには24クラス出力・交差エントロピー・活動回答による入力区間境界がない。

## モデルと学習

`DiscoveryModel`は既存の三階層処理を再利用するが、固定活動ヘッドと40次元の回答履歴変換を持たない。入力は観測値33、presence33、文章32の98次元。Micro/Meso/Macroの隠れ次元は既定48。現在融合表現からPlace、Behavior、現在5尺度を、日次融合表現から日次5尺度を出力する。

観測入力はsession、heartbeat、SwitchBotの変化・周期観測のみ。質問操作の除外、受信時刻によるカットオフ、センサー鮮度、存在マスクは既存の特徴処理を使う。活動回答・場所確認・モデル推定は観測特徴へ混入させない。区間は正時で分割し、24活動の回答を変えても特徴系列が変わらないようにする。

学習損失は次の和である。

1. 最新ビンの観測済み特徴を確率0.2で隠す再構成損失。文章は32座標を一つのブロックとして隠し、隠した値に対応するpresenceも消す。時間周期等は再構成対象から除外する。
2. PlaceとBehaviorを連結して次の1時間の観測特徴を予測するマスク付き二乗損失。
3. 現在・日次の回答済み尺度だけに適用するHuber損失。
4. 同一軸の本人確認IDを近づけ、異なるIDを離す関係損失（各軸の係数0.1）。未確認IDから正解ラベルを作らない。
5. 埋め込みの縮退を抑える分散ペナルティ（各軸の係数0.1）。軸の意味分離を保証するものではない。

実装は自己教師あり損失と教師あり損失の**同時最適化**である。別段階の事前学習や本番TBPTT、参加者間の部分プーリングをこの経路で実装済みとはしない。エポック12、AdamWの学習率0.001・weight decay0.001、バッチ8、seed37、勾配ノルム上限1が既定である。

## パターンと遷移

`DiscoveryMap`は、正規化埋め込みのコサイン類似度を用いる逐次プロトタイプ方式である。既存代表との類似度が0.88未満なら新候補を作る。実装はGrowing Neural Gasの再現ではない。未確認候補の上限は軸ごとに256で、上限時は未知として扱い、最寄りの状態へ強制割当しない。本人確認済みIDはこの候補数制限によって削除しない。

候補の生成と重心更新は**学習側データの時刻順処理で行う**。ライブ推論ではモデルもマップも凍結し、新しい観測の候補化は次回のバッチ再学習で反映する。したがって「オンラインで重みを更新し続ける」「推論のたびに新ノードを永続化する」という実装ではない。

時間遷移は同一マップ内の異なるノードへの隣接割当で、観測間隔が1時間以内のものに限る。観測のない長い区間や候補上限による未知区間を跨いで接続しない。5尺度の予測値は行動マップの距離へ加えない。ただし共有エンコーダのため、行動表現が心理状態の影響を全く受けないとは保証できない。

再学習ごとに元観測から既知IDの表現を再計算する。古いモデルの重心を新しい埋め込みと比較しない。各予測にはモデルIDを保持し、後日の再解析は当時のライブ予測とは別記録にする。

## 因果性・表示・評価

直近28日の観測から最大240時点を選び、最低12時点・3日を要求する。観測日を時間順に約65%/20%/15%へ分ける。回答の対象時刻と受信時刻がその分割の締切を満たす場合だけ追加教師にする。追加後480時点を超える場合はエラーとし、黙って切り捨てない。正規化とプロトタイプは訓練側だけで作り、将来ターゲットも分割境界を跨がせない。

検証指標は将来予測誤差と、有効な現在・日次尺度のHuber損失の和。候補モデルと旧モデルを同じ検証時点・誤差尺度で比較し、悪化しない場合のみ昇格する。テストは明示実行時だけ集計し、昇格判定に使わない。尺度別MAEとPlace/Behaviorの本人確認ID一致率・未知件数を保存する。参加者単位のmacro集計、未知状態検出のprecision/recall、独立な意味注釈による評価は実験計画であり、このCLIの自動出力とは区別する。

ライブ表示では、本人確認2日以上、軸の検証2件以上・一致率0.5以上、上記類似度と次候補との差0.08以上を満たすときだけ`estimated`とする。単一候補、未確認、更新された確認・統合が未学習の場合は断定しない。これらは探索的閾値であり確率の校正値ではない。5尺度も学習10回答・検証3回答未満の項目は数値を表示しない。

未学習、1時間以内の本人端末観測なし、予測時刻より後に学習されたcheckpoint、文章エンコーダの不一致は推定を止める。自己報告による確認はモデル推定と別のsourceとして表示する。

## 導入とロールバック

既存設定のIP、DB、許可端末、参加者、文章モデルは保持する。サーバーを停止しDBとモデルをバックアップした上で、検証用環境の設定に次だけを追加する。

```json
{
  "research_architecture": "discovery",
  "research_enabled": true,
  "discovery_hidden": 48,
  "discovery_epochs": 12
}
```

モデルは`data/models/{participant}/{data_mode}/discovery/`に分離する。旧`active.pt`や旧ContextLSTMを流用せず、新規学習する。`research_architecture`を`legacy`へ戻すと旧経路に戻る。収集設定・元データ・本人確認IDは書き換えない。既定は`legacy`であり、既存運用は変更しない。

新方式では旧生観測GrowingMapに基づく状態別歩数の保存・運動提案と、旧疲労推定に依存する提案判定を停止する。これらを新しい行動状態へ接続する評価は未完了である。自動質問、確認・命名・区間訂正、5尺度推定、振り返りは保持する。

オフライン学習例（既存の全件exportを使用。サンプルの場合は`--data-mode sample`を明示する）：

```sh
python -m research.discovery_cli --export data/private/lifelog-all-p001.json --output data/models/p001/real/discovery --device cpu --evaluate-test
```

期待する出力：JSONの`status: trained`と検証指標。データ不足なら`insufficient_observations`/`insufficient_split`/`insufficient_validation`で、これも異常終了ではない。
意図しない出力：`Traceback`、不完全export、複数参加者、既存の非discovery保存先を示すエラー。既存ディレクトリを消して回避せず、入力と出力先を確認する。

ローカル文章モデルを使う場合は既存と同じ`--text-model`を追加する。未指定は文字n-gram比較用で、意味理解とは扱わない。原文・private export・checkpointをGitに追加しない。

```sh
python -m pytest -q tests/test_discovery.py
python -m pytest -q
```

期待する出力：各テストが`passed`。
意図しない出力：`FAILED`/`ERROR`/import失敗。必要な開発・ML依存を同じ環境へ導入して原因を確認する。実ログでの精度を合成テストから推測しない。

## 検証の限界

GitHub ActionsのLinux CPU環境で合成データの学習からチェックポイント読込・推論、既存回帰テストを確認する。Mac/Ubuntu実機の計測、GPU、実参加者での精度、通知時刻、PlaceとBehaviorの意味分離、校正、介入効果は別途検証が必要である。CIの成功は本番移行や研究上の有効性の証明ではない。
